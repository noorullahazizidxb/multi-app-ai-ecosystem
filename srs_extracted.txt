1. Executive Summary & Decoupled Topology SYS-ARCH-01
This Software Requirements Specification (SRS) defines the production architecture for four commercial AI
applications built inside a single Turborepo + pnpm monorepo. To eliminate single-point-of-failure complexity, prevent
cross-domain coupling, and enable independent scaling, each application operates its own isolated Next.js 15 web
frontend, its own dedicated NestJS backend service, and its own standalone Flutter mobile app, while importing 80%
of core infrastructure from shared workspace packages.

2. Antigravity Execution Directives & Core Principles SYS-PRIN-02
Directive for Antigravity Autonomous Agent: Execute scaffolding sequentially: (1) Initialize root workspace (`pnpm-
workspace.yaml`, `turbo.json`), (2) Build shared TypeScript & Dart packages (`packages/*`), (3) Generate isolated
NestJS backends (`apps/api-*`), (4) Generate Next.js 15 frontends (`apps/web-*`), and (5) Generate Flutter apps
(`apps/mobile-*`). Never cross-import between `apps/*`; all shared code must reside in `packages/*`.
Split-Backend Isolation (KISS): Instead of a monolithic backend where video encoding in ViralMatrix could starve
CPU threads for FreelanceOS invoicing, each backend (`api-resume`, `api-fitness`, `api-freelance`, `api-content`)
compiles into its own lightweight container with its own `.env`, port, and Prisma schema namespace.
SOLID Principles Enforcement: Every NestJS module enforces Single Responsibility (`*.controller.ts` for transport,

6. Multi-Database Prisma v8 Factory (`@repo/db-core`) SYS-DB-06
To satisfy **Dependency Inversion** and **KISS**, business services never write raw SQL. A prebuild script
(`scripts/sync-prisma-provider.ts`) sets the `datasource db` provider in `schema.prisma` (`postgresql`, `sqlite`, or
`mysql`) from `DB_DIALECT`, and `DynamicPrismaService` instantiates the right driver adapter at boot:
// packages/db-core/src/dynamic-prisma.service.ts import { Injectable, OnModuleInit,
OnModuleDestroy } from '@nestjs/common'; import { PrismaClient } from '@prisma/client';
import { PrismaNeon } from '@prisma/adapter-neon'; import { Pool } from
'@neondatabase/serverless'; import { PrismaLibSQL } from '@prisma/adapter-libsql'; import {
createClient } from '@libsql/client'; @Injectable() export class DynamicPrismaService
extends PrismaClient implements OnModuleInit, OnModuleDestroy { constructor() { const
dialect = process.env.DB_DIALECT || 'postgres'; if (dialect === 'neon') { const pool = new
Pool({ connectionString: process.env.DATABASE_URL }); super({ adapter: new PrismaNeon(pool)
}); } else if (dialect === 'turso') { const libsql = createClient({ url:
process.env.TURSO_DATABASE_URL!, authToken: process.env.TURSO_AUTH_TOKEN, }); super({
adapter: new PrismaLibSQL(libsql) }); } else { // Native Prisma connection for standard
PostgreSQL, MySQL, or local file:./dev.db SQLite super({ datasources: { db: { url:
process.env.DATABASE_URL } } }); } } async onModuleInit() { await this.$connect(); } async
onModuleDestroy() { await this.$disconnect(); } }
